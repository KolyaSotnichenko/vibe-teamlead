# Worktrees, branches, merging and PRs

- **A separate copy for each task.** Each task works in its own git worktree in `.vibe-teamlead/worktrees/tasks/<spec-id>/`, on the branch `vibe-teamlead/<spec-id>`. Your working copy is not touched until you decide to merge.
- **Protection in the agents themselves.** Agents are confined to their copy: path checks and the bash command allowlist run as Claude Code hooks, so an agent cannot write outside the worktree or run dangerous commands.
- **Merge** moves the changes into the main branch (the one selected in the project settings, otherwise detected automatically). It is a real git merge: a merge commit in the main branch with the task's whole history. The model helps only with text files git can't merge, and then nothing is committed until you check the listed files and confirm in the task. Open a file there to see what changes in the project and how the result differs from the task; the merge stays staged, and you can edit the files or cancel. If a file stays unresolved, or your uncommitted changes are in the way, nothing changes and the app says why. The project's git hooks don't run for this commit, because the branch could bring its own. The task's worktree and branch are deleted only after the commit.
- **Stage-only merge.** There is a mode where the changes are only staged in the index, so you can commit them manually.
- **Create PR** pushes the task branch and opens a PR through `gh`. It needs a GitHub remote (`origin`); without one the button is disabled.
- **Cleanup is safe.** It never deletes a branch that is not a task branch.
