# Агенти і їхні ролі

Кожен агент — це сесія Claude Code зі своїм промптом (`apps/desktop/prompts/`), набором інструментів і своєю моделлю.

| Агент | Роль |
|---|---|
| **Аналітик ТЗ** (brief_analyst) | Читає завантажений документ і розбиває його на задачі. |
| **Оцінювач складності** | Обирає глибину конвеєра специфікації. |
| **Збирач вимог, дослідник, контекст, discovery** | Готують матеріал для спеки. |
| **Специфікатор** (spec_writer) | Пише `spec.md` з AC. |
| **Критик спеки** | Шукає дірки та суперечності. |
| **Архітектор** | Пише `architecture.md`, ADR і діаграми; рендерить кожну діаграму й виправляє її. |
| **Планувальник** | Пише `implementation_plan.json`: фази, підзадачі, тест-перше, залежності. |
| **Кодер** | Пише код за підзадачами (TDD), комітить, оновлює статус підзадачі. |
| **QA-рев'юер** | Перевіряє AC, тести, UI (браузер), безпеку; пише звіт; відмічає чекбокси спеки. |
| **QA-фіксер** | Виправляє зауваження QA. |
| **Merge resolver** | Розв'язує конфлікти під час злиття. |
| **Генератори commit message / опису PR** | Пишуть повідомлення коміту й текст PR. |
| **PR-рев'юер і спеціалісти** | Рев'ю чужих PR: безпека, якість, логіка, відповідність кодовій базі. |
| **Roadmap, конкурентний аналіз, Ideation, Insights-чат, Changelog** | Утиліти планування й знань. |

## Субагенти

Планувальник, кодер, QA і QA-фіксер можуть доручати частину роботи субагентам-помічникам:

| Субагент | Що робить | Кому доступний |
|---|---|---|
| **Дослідник** (explorer) | Шукає й читає код і повідомляє, де що лежить і як працює. Лише читає. | Планувальник, кодер, QA, QA-фіксер |
| **Запуск тестів** (test runner) | Запускає тести, лінт чи збірку й повідомляє лише про те, що впало. | Кодер, QA, QA-фіксер |
| **Рев'юер** (reviewer) | Перевіряє поточні зміни на відповідність підзадачі чи критеріям приймання. | Кодер, QA-фіксер |

Кожен субагент працює у власному контексті й повертає короткий звіт, тож контекст самого агента лишається на задачі. Субагенти ніколи не змінюють файли, а підзадачі, як і раніше, виконуються по одній, тому конфліктів у worktree не буває.

Поки субагент працює, картка задачі показує, скільки їх працює (наведіть, щоб побачити імена), а в **Логах** під рядком субагента з відступом видно його власні виклики інструментів.

У **«Налаштування → Агенти → Субагенти»** їх можна вимкнути або вибрати для них модель. За замовчуванням вони працюють на моделі самого агента. Для пошуку й тестів зазвичай досить дешевшої моделі, але її має обслуговувати ваш endpoint (наприклад, ваш шлюз).
