# Налаштування — шпаргалка

Налаштування зберігаються самі, коли ви переходите в інший розділ або закриваєте налаштування (×, Escape чи клік поза вікном); кнопки «Зберегти» немає. У заголовку видно «Зберігаю…» і «Збережено». Якщо зберегти не вдалося, налаштування лишаються відкритими з помилкою; закриєте ще раз — незбережені зміни буде відкинуто.

| Розділ | Що там |
|---|---|
| **Вигляд / Відображення / Мова** | Тема (світла/темна/системна), масштаб, мова (українська/англійська). |
| **Інструменти розробника** | IDE і термінал для «відкрити в…», YOLO-режим для ручних терміналів. |
| **Шрифти термінала** | Шрифти терміналів. |
| **Claude** | Режим доступу (API-ключ / підписка), ключі, base URL, перевірка з'єднання. |
| **Інструменти** | Стан вбудованих і зовнішніх інструментів (сканери, Chrome, Docker, Strix, CodeGraph; у Windows також Git for Windows, без якого агенти й перевірки застосунку не можуть виконувати команди). |
| **Агенти** | Профіль моделей, моделі фаз і функцій, Архітектор, форматування, мовні сервери, Security QA (Strix) (див. «Агенти» нижче). |
| **Пам'ять** | Увімкнути/вимкнути, модель ембеддингів. |
| **Шляхи / Оновлення / Сповіщення / Діагностика й журнали** | Шляхи, оновлення, сповіщення, логи для діагностики. |
| **Telegram** | Власний бот у Telegram: токен, пара, які сповіщення він надсилає, ранковий підсумок. Див. сторінку «Telegram». |
| **Проєкт → Загальні** | Модель агентів проєкту, CLAUDE.md, власні перевірки застосунку (команди й змінні, див. «Якість і безпека»), сповіщення. |
| **Проєкт → Черга** | Скільки задач може бути в роботі одночасно (за замовчуванням 1, до 3), автомерж і UI-задачі, що чекають вашого перегляду (див. «Як задача проходить конвеєр»). |
| **Проєкт → GitHub / GitLab / Linear** | Репозиторій, токен, базова гілка, пуш гілок, синхронізація issues. |
| **Майстер налаштування** | Перший запуск: Claude, інструменти, Dev Tools, приватність, пам'ять, облікові записи, документація. Можна запустити знову (див. «Майстер налаштування» нижче). |

## Подробиці

### Агенти

- Профіль моделей, моделі фаз і функцій.
- Архітектор: для кожної задачі / лише для складних / ніколи.
- Форматувати й лінтити після кожної правки: власні prettier/ESLint, Biome, ruff чи gofmt проєкту на кожному файлі, який пише кодер. Типово увімкнено.
- Мовні сервери для агентів: вбудовані сервери TypeScript і Python, gopls/rust-analyzer/clangd, якщо встановлені. Типово увімкнено; вимкніть на дуже великих репозиторіях, якщо бракує пам'яті.
- Security QA (Strix) з власною моделлю й ключем від вибраного провайдера.

### Майстер налаштування

#### Кроки

- Перший запуск: Claude, інструменти, Dev Tools, приватність, пам'ять, облікові записи, документація.
- Можна запустити знову.

#### Крок Claude

- Той самий вибір, що й у Налаштування → Claude: API-ключ (за замовчуванням) або, на власному комп'ютері, токен підписки Claude з кнопкою «Отримати токен». Вибір зберігається одразу. Діалог налаштування GitHub питає так само.

#### Крок «Документація»

- Перед завершенням майстер просить прочитати цю документацію: як працює конвеєр, що роблять агенти, попередній перегляд і чого він не може налаштувати (Docker, зовнішні сервіси з власними ключами), налаштування і витрати.
- «Відкрити документацію» відкриває ці сторінки поверх майстра; закрийте їх, щоб повернутися до кроку.
- Щоб продовжити, позначте «Я прочитав(-ла) документацію або прочитаю її перед початком роботи».

#### Крок GitHub

- Крок облікових записів має необов'язковий вхід у GitHub.
- Якщо пропущено, підключіть його пізніше в Проєкт → GitHub або на вкладці «CI».
- Вихід із кроку скасовує вхід, що триває.
- GitHub — це два кроки: вхід, а потім установлення застосунку Vibe Teamlead на GitHub і вибір репозиторіїв, якими він може користуватися.
- Майстер просить зробити другий крок і перевіряє знову, коли ви повертаєтеся.
- Щоб додати репозиторій пізніше, відкрийте https://github.com/settings/installations, виберіть застосунок Vibe Teamlead і додайте його.

## Оновлення

Застосунок сам завантажує оновлення. Потім він перезапускається після 10-секундного відліку, який можна зупинити кнопкою **Пізніше**; відкладене оновлення встановиться, коли ви закриєте застосунок. Поки працюють агенти, застосунок чекає, доки вони закінчать, бо перезапуск зупинив би їх.
