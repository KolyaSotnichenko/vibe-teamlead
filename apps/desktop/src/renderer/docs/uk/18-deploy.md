# Деплой

«Деплой» у сайдбарі (гаряча клавіша Y) показує, що відбувається з кодом проєкту після того, як його запушено: запуски GitHub Actions його репозиторію наживо і те, куди код вийшов у продакшн.

## Запуски

Останні запуски GitHub-репозиторію проєкту перелічено ліворуч. Виберіть один, і праворуч відкриється його граф: джоби workflow, згруповані в етапи за їхніми `needs`. Джоби, які не залежать одне від одного, стоять в одному етапі; ті, що на них чекають, йдуть у наступному.

Статус живий. «Деплой» оновлюється кожні 5 секунд, поки щось виконується, і кожні 60 секунд в інший час. Оновлення йде лише поки «Деплой» відкритий і вікно видиме.

Клацніть джоб, щоб побачити його кроки, які оновлюються, поки він виконується. Його лог, останні 2 000 рядків, з'являється, коли джоб завершиться. GitHub зберігає логи обмежений час, тож для старого запуску може бути написано, що GitHub більше не зберігає його лог; **Повний лог на GitHub** відкриває його там.

Джоб, що запускається кілька разів (матриця, наприклад окремий образ для кожного застосунку, або reusable workflow), — це один блок у графі. Частини його назви, які GitHub підставляє під час запуску (`${{ … }}`), показано як `…`; наведіть на блок, щоб побачити назви його джобів, і клацніть, щоб вибрати, чиї кроки й лог дивитися. Блок на етапі **Деплой** не показує тривалості; наведіть на нього або перейдіть до нього клавіатурою, щоб побачити, як давно цей деплой вийшов у продакшн (коли він уже там).

## Деплой і посилання на продакшн

Етап **Деплой** і посилання **Продакшн** беруться з GitHub Deployments, а не з workflow. Хостинг, який звітує в GitHub, наприклад Vercel через інтеграцію з GitHub, з'являється там зі своїм статусом і логом. Якщо ніхто не повідомляє про деплої, граф показує лише джоби workflow.

## Що потрібно

- **Вхід у GitHub і встановлений застосунок.** Це два кроки: увійдіть, а потім установіть застосунок Vibe Teamlead на GitHub і надайте йому доступ до репозиторію. Якщо входу немає, у «Деплої» є кнопка **Під'єднати GitHub**; вона просить і про встановлення, якщо застосунок ще не встановлено.
- **Репозиторій проєкту на GitHub.** Без нього «Деплой» про це каже і перевіряє знову щохвилини.
- **Нові дозволи, підтверджені один раз.** Дозволи застосунку в GitHub тепер включають читання Actions і Deployments. GitHub просить підтвердити їх один раз: відкрийте https://github.com/settings/installations, виберіть застосунок Vibe Teamlead і прийміть запит. Коли доступу бракує, «Деплой» показує поруч із повідомленням кнопку **Керувати доступом на GitHub**.

## Коли щось не так

- **Застосунок не може читати Actions репозиторію:** дозволи вище ще не підтверджено, або застосунок не має доступу до цього репозиторію. **Керувати доступом на GitHub** відкриває сторінку, де це виправити.
- **GitHub не знаходить цей репозиторій:** репозиторій приватний і застосунок не має до нього доступу, або його більше немає. Якщо застосунок не встановлено для власника репозиторію, **Установити застосунок на GitHub** відкриває сторінку встановлення; інакше **Керувати доступом на GitHub** дає змогу додати репозиторій до застосунку (https://github.com/settings/installations → застосунок Vibe Teamlead → додайте репозиторій).
- **Ліміт запитів GitHub вичерпано:** «Деплой» робить паузу до часу, який показує, і далі продовжує сам.
- **GitHub не відповідає:** «Деплой» каже про це й пробує ще раз. Лог, який не завантажився, теж запитується знову.

## Акаунт Vercel

Налаштування → Vercel підключає акаунт Vercel, яким «Деплой» налаштовує хостинг. **Підключити Vercel** першого разу завантажує Vercel CLI (близько 180 МБ, перевіряється перед використанням), показує код і відкриває сторінку входу Vercel у браузері; підтвердьте там код. **Скасувати** зупиняє вхід, і нічого не зберігається. Вхід зберігається у власній теці застосунку, а не у вашому Vercel CLI, і поновлюється сам. Можна натомість вставити токен Vercel: він зберігається зашифрованим на цьому Mac і використовується замість входу через браузер. **Відключити** прибирає обидва з цього Mac (на Vercel нічого не відкликається).

## Середовище: налаштування деплою

У «Деплої» дві вкладки: **Запуски** та **Середовище**. Поки деплой для проєкту не налаштовано, обидві пропонують **Налаштувати деплой**.

Налаштування на вкладці «Середовище» йде крок за кроком і показує кожен: репозиторій GitHub (якщо в проєкту його нема, створюється приватний, і в нього пушиться головна гілка), проєкт Vercel, підключений до цього репозиторію, далі деплой увімкнено. Якщо у вашому акаунті Vercel є команди, спершу оберіть, куди йде проєкт: в особистий акаунт чи в команду. Крок, що зупинився, можна запустити знову кнопкою **Спробувати ще раз**; нічого не створюється двічі.

**Потрібно від вас** — те, що можете зробити лише ви, кожне зі своєю кнопкою: підключити Vercel чи GitHub (відкриває Налаштування), встановити застосунок Vibe Teamlead або дати GitHub-застосунку Vercel доступ до репозиторію (відкриває GitHub), обрати наявний проєкт Vercel для репозиторію чи створити новий, або взяти до відома, що репозиторій публічний.

Після налаштування вкладка показує, що вже є: репозиторій і чи він публічний, проєкт Vercel, адресу продакшну й базу даних. Відтоді кожне злиття в головну гілку проєкту пушиться на GitHub, а Vercel його деплоїть; останній пуш і чи він вдався видно вгорі вкладки.

## Змінні й база даних

**Додати змінну** зберігає змінну в проєкті Vercel для Production, Preview або обох, а якщо позначити — ще й як секрет GitHub Actions. Значення вводиться в поле пароля й більше ніколи не показується; у списку лише назви, де вони діють і чи вони є також у GitHub. Коли один бік зберіг, а інший — ні, діалог каже, який саме.

**Додати базу даних** додає безкоштовну базу Postgres (Neon) до проєкту Vercel. Першого разу Vercel просить прийняти умови Marketplace для Neon: вкладка показує посилання на правила разом із сайтом, який кожне відкриває, і нічого не приймається, доки ви не натиснете **Прийняти й додати базу даних**. Якщо Vercel потребує кроку, який можна зробити лише в його панелі, вкладка дає туди посилання.

## Що далі

Перевірка готовності та прев'ю з'являться в наступних версіях «Деплою».
