# Якість і безпека

| Шар | Що робить |
|---|---|
| **TDD + AC** | Кожна вимога має тест; QA перевіряє, що тест справді її тримає. |
| **Перевірки застосунку** | Застосунок сам запускає typecheck і тести проєкту на чистій копії закоміченого коду, перед кожним QA-рев'ю і після злиття, і читає справжні коди виходу. Падіння блокує схвалення, лише якщо та сама перевірка проходить на коміті, з якого задача почалась. Також блокують видалений файл тестів, вимкнений наявний тест і змінений скрипт `test` або `typecheck`. Тест, що запускається лише за наявності ресурсу, вимкненим не вважається. Якщо перевірка нічого не може сказати (падає й на базі, немає інструмента), задача не блокується, а в лозі написано, що її не перевірено. Команди визначаються для npm, pnpm, yarn, bun, Python, Go, Rust, Maven, Gradle, .NET, Ruby, PHP і Swift у корені проєкту; інші задаються в налаштуваннях проєкту. Якщо compose-файл проєкту називає базу (Postgres, MySQL, Redis, Mongo) і Docker запущений, застосунок для кожного прогону запускає порожню тимчасову базу, застосовує міграції (Prisma, Drizzle, Django, Alembic, Rails, Laravel), бере налаштування з `.env.example` і потім видаляє базу, тож налаштовувати нічого не треба. Без Docker у лозі написано, що перевірку не вдалося завершити, а задача не блокується. Міграції запускаються лише на цій тимчасовій базі, а налаштування з `.env.example`, що вказують на будь-яку іншу базу, не використовуються. У вікні задачі видно, що пройшло, а картка повідомляє, коли перевірки сказали не все. Ці перевірки запускають код самої задачі з вашими правами, без API-ключів в оточенні, і не в пісочниці. |
| **gitleaks** | Секрети в коді блокують схвалення. |
| **OSV-Scanner** | Вразливі залежності блокують схвалення. |
| **Semgrep** | Статичний аналіз змінених файлів (ін'єкції, небезпечні API; правила його реєстру рівня ERROR) блокує схвалення. Працює лише якщо Semgrep встановлено (`brew install semgrep` або `pip install semgrep`); інакше, або коли правила не вдається завантажити, гейт пропускається і звіт про це каже. Якщо Semgrep не зміг розібрати частину файлів або повідомив про помилку самого запуску, звіт каже «CLEAR (PARTIAL: …)», а вкладка «Безпека» називає, що не було охоплено, щоб ви переглянули ці файли самі; якщо він не зміг просканувати жодного файлу, гейт вважається таким, що не спрацював. |
| **Дизайн-перевірка** | Статична перевірка доданих рядків UI на токени дизайн-системи + рев'ю скріншотів (див. «Дизайн-система і Storybook»). |
| **Браузерна перевірка** | QA відкриває застосунок у Chrome (Playwright / DevTools MCP), робить скріншоти й дивиться консоль. |
| **Strix** | Пентест у Docker (опційно). Знахідки заданого вами рівня блокують задачу й ідуть до QA fixer. Дрібніші її не зупиняють: застосунок оформлює їх однією новою задачею на дошці, без повторів, і ви запускаєте її, коли вважаєте за потрібне. |
| **Хуки безпеки** | Межі шляхів, список заборонених команд (усе інше дозволено), заборона вбивати процеси самого застосунку. |
| **Ізоляція оточення** | Агенти працюють з власною конфігурацією Claude Code (`~/.vibe-teamlead/claude-code`), а не з вашою `~/.claude`. Змінні оточення фільтруються. |

Сканери (gitleaks, OSV-Scanner), Claude Code, CodeGraph, Superpowers і Mermaid вбудовані в застосунок і нічого не треба ставити окремо. Semgrep не вбудований (це Python-пакет): встановіть його, якщо хочете цей гейт. Docker і Chrome потрібні лише для Strix і браузерних перевірок. Стан усіх інструментів видно в «Налаштування → Інструменти».
