# Моделі й доступ до Claude

## Доступ («Налаштування → Claude»)

Два режими, перемикач угорі:
- **API-ключ:** ключ Anthropic або сумісного шлюзу плюс опційний **base URL**. Так працює, наприклад, Meter → Ollama: `https://gw.metergateway.com/ollama`.
- **Підписка Claude:** токен з `claude setup-token`, лише для власного комп'ютера (у збірках для інших людей не вмикати). Base URL не використовується.

Обидва ключі зберігаються окремо, зашифровані в Keychain macOS. Сесії беруть ключ лише обраного режиму, без тихої підміни. Кнопка «Перевірити з'єднання» тестує ключ обраного режиму.

## Моделі

- **Профіль агентів** («Налаштування → Агенти»): моделі та рівень «мислення» для кожної фази — спека, планування, код, QA.
- **Свої моделі для фаз:** можна вказати модель окремо для кожної фази. Список береться з вашого endpoint (Anthropic або шлюзу). QA-фіксер працює на моделі фази «Код», бо редагує код; модель QA — для рев'юера.
- **Задача і налаштування:** перед кожним запуском задача бере моделі й рівні мислення, вказані тут зараз, тому після зміни провайдера чи моделей міняти їх треба лише тут. Запущена задача працює на своїх моделях до кінця запуску. Виняток — задача, для якої ви вибрали інші моделі під час створення чи редагування: вона лишає їх, поки ви не повернете такі самі, як тут.
- **Моделі функцій:** окремі моделі для Insights, Roadmap, Ideation, аналізу ТЗ, Deploy readiness (типово Sonnet, низьке мислення) тощо. Аналіз ТЗ наслідує модель Roadmap, поки не задано свою. Модель «Utility» пише повідомлення комітів, описи PR і changelog.
- **Модель субагентів:** «Налаштування → Агенти → Субагенти», за замовчуванням та сама, що в агента.
- **Не-Claude моделі** (glm, kimi, qwen через шлюз) працюють. Застосунок підставляє обрану модель і туди, де Claude Code інакше звертався б до своїх «малих» моделей.
