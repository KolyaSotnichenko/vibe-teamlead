# Інструменти агентів: MCP і скіли

| Що | Для чого |
|---|---|
| **Інструменти Vibe Teamlead** (`mcp__vibe-teamlead__*`) | Статус підзадач, прогрес збірки, запис відкриттів і підводних каменів, статус QA, пам'ять (`search_memory`, `remember`), рендер діаграм (`render_diagram`: draw.io/Mermaid → PNG). |
| **CodeGraph** (`mcp__codegraph__*`) | Карта коду . |
| **Context7** | Актуальна документація бібліотек (хостований HTTP-сервер). Допомагає не писати за застарілим API. Опційно з ключем `CONTEXT7_API_KEY`. |
| **Браузер** (Playwright / Chrome DevTools MCP) | QA перевіряє UI. Запускається лише тоді, коли задача змінила UI-файли. |
| **Electron MCP** | QA для Electron-застосунків. |
| **Linear** | Робота із задачами Linear (якщо підключено). |
| **Власні MCP-сервери** | Додаються в MCP Overview і призначаються агентам. |
| **Мовні сервери** (вбудовані: TypeScript/JavaScript через typescript-language-server, Python через pyright; з машини: gopls, rust-analyzer, clangd, якщо встановлені) | Кодер і QA-фіксер отримують інструмент `LSP` (перехід до визначення, посилання, hover) і діагностику типів одразу після кожної правки, тож не запускають увесь typecheck, щоб побачити помилки. Які сервери отримує сесія, залежить від мов проєкту (з `project_index.json` або сканування package.json / pyproject.toml / go.mod / Cargo.toml); журнал задачі каже `LSP: typescript, python` або чому серверів немає. Вбудовані сервери працюють на Node, що постачається з CodeGraph. Перемикач: «Налаштування → Агенти». |
| **Superpowers** (вбудований плагін) | Набір скілів Claude Code: TDD, дебаг, планування тощо. |
| **frontend-design** (вбудований плагін) | Скіл frontend-design від Anthropic (Apache-2.0). Його отримує кодер, коли підзадача зачіпає UI-файли (`.tsx`, `.css`, `.vue` …) або не називає файлів у проєкті з інтерфейсом. Дизайн-система проєкту і спек мають пріоритет; скіл відповідає за ієрархію, розкладку, тексти й те, щоб інтерфейс не виглядав шаблонним. Підзадачі з API чи даними його не завантажують. |
| **UX-рев'ю** (вбудований плагін) | Рев'юер QA задачі, що змінила UI-файли, відкриває змінені сторінки в браузері (Playwright): на ширині 375 і 1280 пікселів, з клавіатури, у темній темі, якщо вона є в дизайн-системі, у порожньому, завантажувальному й помилковому станах, і перевіряє, як людина до них дістається. Звіряє з Web Interface Guidelines від Vercel (MIT) і чеклистами audit та harden з Impeccable (Apache-2.0). Дизайн-система і спек мають пріоритет. Проблема, через яку людина не може користуватися сторінкою, блокує схвалення; питання смаку йдуть у «UX notes» у звіті. Задачі без змін інтерфейсу його не завантажують. |
| **Скіл architecture** | Стандарт документа архітектури, діаграм і циклу перевірки для архітектора. |
