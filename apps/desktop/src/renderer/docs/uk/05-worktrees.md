# Worktree, гілки, злиття і PR

- **Окрема копія для кожної задачі.** Кожна задача працює в окремому git worktree у `.vibe-teamlead/worktrees/tasks/<spec-id>/`, на гілці `vibe-teamlead/<spec-id>`. Ваша робоча копія не чіпається, поки ви не вирішите злити.
- **Захист у самих агентах.** Агенти обмежені межами своєї копії: перевірка шляхів і список заборонених bash-команд працюють як хуки Claude Code, тож агент не може писати поза worktree чи запускати небезпечні команди.
- **«Злити»** переносить зміни в основну гілку (обрана в налаштуваннях проєкту, інакше визначається автоматично). Це справжній git merge: коміт злиття в основній гілці з усією історією задачі. Подробиці — у розділі «Злиття докладно» нижче.
- **Злиття лише в індекс.** Є режим, де зміни лише додаються в індекс і можна закомітити вручну.
- **«Створити PR»** пушить гілку задачі й відкриває PR через `gh`. Потрібен віддалений репозиторій GitHub (`origin`); без нього кнопка неактивна.
- **Прибирання безпечне.** Воно ніколи не видаляє гілку, яка не є гілкою задачі. Залишену теку, підтеки якої забороняють видалення через ACL (macOS), спершу очищають від цих записів, а потім видаляють.
- **Залежності.** Новий worktree отримує теки залежностей проєкту (`node_modules`, venv Python тощо): їх підключають, відтворюють або копіюють з основної копії, як сказано в індексі проєкту. На Windows підключення — це junction, а файл, який не можна підключити, копіюється; довгі шляхи для worktree ввімкнено.

## Злиття докладно

### Черга і підготовка

- Злиття одного проєкту йдуть по одному: якщо задач кілька, кожна чекає своєї черги і будується на попередній.
- Перед злиттям застосунок вливає свіжу основну гілку в задачу, у її теці, тому ваш проєкт лишається без змін.

### Якщо основна гілка пішла вперед

- Агент перевіряє результат власними typecheck і тестами проєкту, навіть коли git злив усе без конфлікту.
- Конфлікти він розв'язує, маючи доступ до всього проєкту.
- Він працює на моделі з «Налаштування → Агенти → Службові».
- Якщо він нічого не змінив, злиття йде далі.
- Якщо змінив код, спершу ви побачите в задачі перелік файлів і його звіт. Відкрийте файл, щоб побачити, що зміниться в проєкті і чим результат відрізняється від задачі, тоді злийте або скасуйте.
- Скасування повертає задачу як було.
- Якщо агент здається, наприклад коли дві задачі хочуть несумісного, задача повертається як було, у проєкт нічого не потрапляє, а застосунок пояснює причину.
- Агента, який за 30 хвилин не завершив роботу, зупинено, тож він не тримає задачі за собою в черзі.

### Поки воно триває

- Вікно задачі можна закривати будь-коли.
- Картка покаже, що задача зливається, що злиття треба перевірити або що воно не вдалось, а сама задача пояснить причину.

### Після злиття

- Застосунок сам запускає перевірки проєкту, і падіння, яке принесло злиття, повертає задачу назад, що б не повідомив агент.

### Коли застосунок відмовляє

- Застосунок відмовить, якщо заважають ваші незакомічені зміни.
- Так само буде, якщо в теці задачі є незакомічені зміни, яких QA не перевіряв. Застосунок назве їх, а ви закомітите їх у гілку задачі або відкинете.

### Хуки і прибирання

- Git-хуки проєкту для цього коміту не запускаються, бо гілка могла б принести власні.
- Worktree і гілка задачі видаляються лише після коміту.
