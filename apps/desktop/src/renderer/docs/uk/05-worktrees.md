# Worktree, гілки, злиття і PR

- **Окрема копія для кожної задачі.** Кожна задача працює в окремому git worktree у `.vibe-teamlead/worktrees/tasks/<spec-id>/`, на гілці `vibe-teamlead/<spec-id>`. Ваша робоча копія не чіпається, поки ви не вирішите злити.
- **Захист у самих агентах.** Агенти обмежені межами своєї копії: перевірка шляхів і allowlist bash-команд працюють як хуки Claude Code, тож агент не може писати поза worktree чи запускати небезпечні команди.
- **«Злити»** переносить зміни в основну гілку (обрана в налаштуваннях проєкту, інакше визначається автоматично). Це справжній git merge: коміт злиття в основній гілці з усією історією задачі. Модель допомагає лише з текстовими файлами, які git не може злити сам, і тоді коміту немає, доки ви не перевірите перелічені файли й не підтвердите це в задачі. Відкрийте там файл, щоб побачити, що зміниться в проєкті і чим результат відрізняється від задачі; злиття лишається в індексі, файли можна поправити або скасувати злиття. Якщо файл лишається нерозв'язаним або заважають ваші незакомічені зміни, нічого не змінюється, а застосунок пояснює причину. Так само буде, якщо в теці задачі є незакомічені зміни, яких QA не перевіряв: застосунок назве їх, а ви закомітите їх у гілку задачі або відкинете. Git-хуки проєкту для цього коміту не запускаються, бо гілка могла б принести власні. Worktree і гілка задачі видаляються лише після коміту.
- **Злиття лише в індекс.** Є режим, де зміни лише додаються в індекс і можна закомітити вручну.
- **«Створити PR»** пушить гілку задачі й відкриває PR через `gh`. Потрібен віддалений репозиторій GitHub (`origin`); без нього кнопка неактивна.
- **Прибирання безпечне.** Воно ніколи не видаляє гілку, яка не є гілкою задачі.
