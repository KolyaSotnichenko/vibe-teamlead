# Екрани застосунку

## Збірка (Build)

| Екран | Що там |
|---|---|
| **Команда зараз** (бічна панель) | Піксельний тімлід показує, що робить команда; під ним лічильники (див. «Команда зараз» нижче). |
| **Вкладки проєктів** (угорі) | Відкриті проєкти; «+» додає новий. Поруч — скільки токенів витрачено на проєкт (і вартість через Anthropic API); натисніть, щоб побачити розподіл (див. «Вкладки проєктів» нижче). |
| **Канбан** | Задачі за колонками: *Планування → Черга → У роботі → AI-перевірка → Ваша перевірка → Готово*. Дошка оновлюється наживо (див. «Канбан» нижче). |
| **Agent Terminals** | Термінали з Claude Code, кожен у своєму worktree, для ручної роботи поруч з агентами. Новий термінал — ⌘T на macOS, Ctrl+T на Windows. |
| **Перегляд** | Застосунок проєкту з основної гілки, запущений просто у вікні: видно, що збудували агенти, нічого не запускаючи самі. Працює, лише поки «Перегляд» відкритий (див. «Перегляд»). |
| **CI** | Запуски GitHub Actions репозиторію проєкту наживо: граф джобів кожного запуску, кроки й лог джоба, те, що заважає CI проходити, і потрібні секрети (див. «CI»). |
| **Worktrees** | Ізольовані копії репозиторію для кожної задачі: скільки комітів попереду, скільки змінено файлів. Тут же «Злити», «Створити PR», «Скопіювати шлях», «Видалити». Теки, що лишились після невдалого прибирання, позначено як «осиротілі». |
| **GitHub Issues / PRs**, **GitLab Issues / MRs** | З'являються, коли підключено GitHub або GitLab: перетворення issue на задачу, AI-рев'ю pull request-ів. |

### Команда зараз

- Піксельний тімлід показує, що робить команда, одним настроєм за пріоритетом: помилка, запитання до вас, задача на перевірку, робота, QA, черга, спокій.
- Через годину без подій він засинає, після злиття підстрибує від радості.
- Коли застосунок відкривається, він махає рукою; натисніть на нього, щоб привітатися.
- Він пищить, як дроїд, коли агент питає, задача готова чи впала, і після злиття.
- Голос вимикається в «Налаштування → Сповіщення → Голос тімліда».
- Під ним лічильники.

### Вкладки проєктів

- Вкладки — це відкриті проєкти; «+» додає новий.
- Поруч — скільки токенів витрачено на проєкт (і вартість через Anthropic API). Натисніть, щоб побачити розподіл за видами токенів і агентами.
- Токени за підпискою рахуються, але без ціни.

#### Ціни через шлюз

- Для шлюзу введіть у цьому вікні, скільки він бере за мільйон токенів кожної моделі. Там моделі з налаштувань і ті, що вже працювали.
- Нова ціна діє від цього дня, а старіші сесії лишаються за старою.
- Тоді видно долари за моделями, задачами й видами токенів.
- Власних цін шлюзу застосунок не має, а модель без ціни до суми не входить.

### Канбан

- Задачі за колонками: *Планування → Черга → У роботі → AI-перевірка → Ваша перевірка → Готово*.
- Задача зі створеним pull request показується в *Готово*, задача з помилкою — у *Ваша перевірка*.
- Дошка оновлюється наживо.
- Задачі з черги стартують самі, з урахуванням ліміту паралельних задач.
- Коли чергу призупинено (команда Telegram `/stop_all`), колонка «Черга» показує **Paused** з кнопкою **Resume**, і жодна задача з черги не стартує.
- Меню ⋮ на картці переносить задачу в іншу колонку або видаляє її (після підтвердження; задачу, що виконується, спершу зупиніть).

## Планування (Plan)

| Екран | Що там |
|---|---|
| **Roadmap** | Дорожня карта продукту: агенти аналізують проєкт (і за бажанням конкурентів) та пропонують фічі за пріоритетами. Фічу можна перетворити на задачу. |
| **Ideation** | Генерація ідей за типами: покращення коду, якість, документація, продуктивність, безпека, UI/UX. Ідею можна перетворити на задачу. |
| **Insights** | Чат про ваш код. Агент читає проєкт (через CodeGraph і файли), бачить пам'ять, може запам'ятати нове. Видно, які інструменти він викликає. |

## Знання (Knowledge)

Сторінок знань немає в бічній панелі: вони праворуч у рядку стану внизу вікна — **Context** (клавіша C), **Changelog** (L), **MCP Overview** (M) і **Документація** (H), а за ними шестірня налаштувань. Відкрита позначена так само, як у бічній панелі. У вузькому вікні видно лише їхні значки; наведіть курсор, щоб побачити назву і клавішу.

| Екран | Що там |
|---|---|
| **Context → Індекс проєкту** | «Паспорт» проєкту: сервіси, фреймворки, команди тестів, порти. Кнопка «Проаналізувати проєкт». |
| **Context → Спогади** | Що агенти запам'ятали про цей проєкт. |
| **Context → Дизайн-система** | Правила й токени UI проєкту, перевірка дизайну в QA, Storybook (див. «Дизайн-система і Storybook»). Частина Screens містить бібліотеку wireframe і екранів, які намалював дизайнер (див. «Дизайн перед кодом»). |
| **Context → Архітектура** | Хмарна архітектура проєкту (TerraVision, експериментально): остання спроєктована архітектором і остання намальована з коду Terraform після злиття, поруч; рішення (ADR) злитих задач; кнопка «Спроєктувати хмарну архітектуру», задача якої закінчується після архітектора (див. «Діаграми хмарної архітектури»). |
| **Changelog** | Генерація changelog із завершених задач, історії git або порівняння гілок. |
| **MCP Overview** | Які MCP-сервери та інструменти має кожен агент; власні MCP-сервери; перемикачі Context7, Linear, браузерних інструментів. |

### Рядок стану

Тонкий рядок уздовж низу всього вікна, під бічною панеллю і сторінкою. Ліворуч — що відбувається зараз; клік відкриває місце, де це живе:

- **Питання до вас** — агент чекає на вашу відповідь (вермільйон); відкриває питання.
- **У роботі** і **у черзі** — задачі проєкту, над якими працюють і які чекають у черзі; відкривають дошку.
- **Чергу призупинено** — поки черга не запускає нових задач (наприклад, після /stop_all у Telegram-боті); відкриває дошку.
- **CI на main** — коли CI налаштовано і перевірка готовності CI записала запуск на main: проходить, падає (вермільйон) або без вердикту; відкриває CI → Готовність CI. Рядок показує лише те, що застосунок уже знає; сам GitHub він не опитує.

Без відкритого проєкту ліва частина порожня, хіба що чекає питання. Праворуч — сторінки знань і налаштування.

## Вікно задачі

| Вкладка | Що там |
|---|---|
| **Огляд** | Опис, статус, прогрес підзадач, кнопки «Почати», «Зупинити», «Злити», «PR». Повідомлення про CI: статус CI гілки задачі, чому його нема (CI не налаштовано, публічний репозиторій) або чому не вдався останній пуш його гілки (див. «CI» → CI на картках задач). |
| **Workspace → Spec** | Критерії приймання з результатами QA (✓ / ✗ / не перевірено) і хто їх покриває; `spec.md` з відміченими чекбоксами. |
| **Workspace → Plan** | Граф залежностей підзадач (зліва направо або зверху вниз, перемикач у кутку) і хронологія «що відбувалось». |
| **Workspace → Architecture** | Діаграми (draw.io відкриваються в draw.io; SVG, як-от хмарна діаграма архітектора з TerraVision, теж показуються), `architecture.md` з вбудованими діаграмами, ADR. |
| **Workspace → Security** | Результати гейтів і Strix: знахідки з рівнем серйозності. |
| **Design** | Wireframe і екрани, які дизайнер намалював для задачі зі змінами UI: коментар до місця, затвердження, прототип, а згодом — чим збудована сторінка відрізняється від дизайну (див. «Дизайн перед кодом»). |
| **Workspace → Preview** | Власний застосунок задачі до злиття (див. «Preview»). Є, поки задача чекає перевірки. |
| **Workspace → Storybook** | Storybook з worktree задачі — компоненти наживо до злиття (є, коли задача змінила UI-файли в теці Storybook). |
| **Підзадачі** | Список підзадач і їхні статуси. |
| **Логи** | Що робив кожен агент за фазами (планування, код, перевірка): виклики інструментів, вивід команд, помилки. |
| **Файли** | Файли спеки. |
